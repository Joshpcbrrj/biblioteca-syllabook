# Dossiê c03: Como o Git pensa

Original: Entendendo como o Git funciona; Ciclo de vida dos status; .gitignore.

## Fatos (checados em 2026-11-21; docs locais do Git 2.56)

- `git init` cria `.git/` ("Initialized empty Git repository in ...").
- Commit = snapshot do projeto; arquivos que não mudaram não são copiados de novo, o commit aponta para a versão já guardada. https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F
- Hash SHA-1 de 40 caracteres hexadecimais; `git init --object-format=sha256` existe. (mesma fonte; git-init)
- Três áreas: diretório de trabalho (working tree), staging area (index), repositório (.git). (mesma fonte)
- Status: untracked; tracked = unmodified, modified, staged. https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository
- gitignore: "Files already tracked by Git are not affected"; `!` reinclui, mas "It is not possible to re-include a file if a parent directory of that file is excluded"; barra no início ou no meio ancora no nível do .gitignore; `**/foo` qualquer pasta; `abc/**` tudo dentro. gitignore (local).
- `git rm --cached` para de rastrear sem apagar do disco. git-rm.
- `git check-ignore -v <arquivo>` mostra a regra que ignora. git-check-ignore.
- Modelos prontos: https://github.com/github/gitignore

## Exemplos novos

- Projeto `receitas`: `index.html`, `receitas/bolo-de-cenoura.md`, `.env` com chave falsa, pasta `rascunhos/`, `servidor.log`.

## Erros comuns

- Pôr no .gitignore um arquivo já commitado e achar que parou de ser rastreado.
- `!rascunhos/publicar.md` com `rascunhos/` ignorada: não volta → usar `rascunhos/*`.
- Achar que `git add` já grava no histórico.
- Editar depois do `git add` e commitar sem novo `add`: a edição nova fica de fora.
