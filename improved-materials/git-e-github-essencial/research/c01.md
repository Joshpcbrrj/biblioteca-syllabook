# Dossiê c01: Por que controlar versões

Original: O que é controle de versão; O que é o Git; Git não é GitHub.

## Fatos (checados em 2026-11-21)

- Git nasceu em 2005, na comunidade do kernel Linux, "in particular Linus Torvalds", quando o BitKeeper deixou de ser gratuito ("free-of-charge status was revoked"); o Linux usava o BitKeeper desde 2002. https://git-scm.com/book/en/v2/Getting-Started-A-Short-History-of-Git
- Metas de projeto: velocidade; design simples; suporte forte a desenvolvimento não linear (milhares de branches paralelas); totalmente distribuído; eficiente em projetos grandes como o kernel. (mesma fonte)
- Centralizados: CVS, Subversion. Distribuídos: Git, Mercurial. https://git-scm.com/book/en/v2/Getting-Started-About-Version-Control
- Outros serviços que hospedam o mesmo Git: GitLab, Bitbucket.
- NÃO afirmar a data da compra do GitHub pela Microsoft (fonte oficial fora do ar).

## Exemplos novos

- Pasta de uma lanchonete com `cardapio.txt`, `cardapio-final.txt`, `cardapio-final-2.txt`, `cardapio-final-revisado-joana.txt`: quem mudou o preço do X-salada, e quando?
- Histórico impresso de exemplo (`git log --oneline`) para o leitor ler antes de instalar o Git.

## Erros comuns

- "Git e GitHub são a mesma coisa"; "preciso de internet para commitar".
- "Distribuído = sem servidor": o servidor existe, mas não é o único lugar com o histórico.

## Decisão

- Cap. 1 sem terminal (instalação é no cap. 2): a prática é ler e interpretar históricos impressos.
