# Dossiê c05: Desfazendo erros com segurança

Original: Voltando no tempo; Desfazendo e refazendo; Desfazendo com checkout; Desfazendo com revert e reset.

## Fatos (checados em 2026-11-21; docs locais do Git 2.56)

- `git switch` e `git restore` surgiram no Git 2.23 (RelNotes/2.23.0).
- `git restore <arq>` (trabalho a partir da staging), `--staged` (staging a partir de HEAD), `--source=<commit>`. git-restore.
- `git commit --amend` substitui o último commit (hash novo).
- `git switch --detach <commit>`; commits soltos em detached HEAD só pelo reflog.
- `reset --soft`, `--mixed` (padrão), `--hard`. git-reset.
- `git revert <commit>`, `--no-edit`; conflito → `git revert --continue`. git-revert.
- Reflog: entradas expiram em 90 dias por padrão; as inalcançáveis, em 30 dias. git-gc (gc.reflogExpire, gc.reflogExpireUnreachable).

## Diagrama-chave

- `flow` "o que você quer desfazer?" → restore / restore --staged / amend / reset / revert.

## Erros comuns

- `reset --hard` com alterações não commitadas (perdidas de vez).
- `reset` em commit já enviado.
- Confundir revert (desfaz um commit) com "voltar para" um commit.
