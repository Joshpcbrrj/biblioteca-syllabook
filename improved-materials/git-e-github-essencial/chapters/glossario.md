# Glossário

Cada termo em uma frase, com o termo em inglês quando ele aparece na tela e o capítulo que o explica.

- **Alerta (*alert*):** bloco destacado do Markdown do GitHub, como `> [!NOTE]`, para notas e avisos. [Capítulo 10](10-projeto-curriculo-online.md)
- **Bare repository:** repositório sem pasta de trabalho, só com o conteúdo do `.git`, usado como remoto. [Capítulo 8](08-repositorios-remotos.md)
- **Blob:** objeto do Git que guarda o conteúdo de um arquivo, identificado pelo hash. [Capítulo 3](03-como-o-git-pensa.md)
- **Branch:** ponteiro com nome para um commit, que avança a cada commit novo feito nela. [Capítulo 6](06-branches-stash-e-merge.md)
- **Branch de rastreamento (*remote-tracking branch*):** cópia local, como `origin/main`, de onde estava uma branch do remoto no último contato. [Capítulo 8](08-repositorios-remotos.md)
- **Clone:** cópia completa de um repositório, com todo o histórico, criada com `git clone`. [Capítulo 8](08-repositorios-remotos.md)
- **Colaborador (*collaborator*):** pessoa convidada pelo dono que pode enviar commits direto para o repositório. [Capítulo 9](09-colaborando-no-github.md)
- **Commit:** foto (snapshot) do projeto guardada no histórico, com autor, data, mensagem e o commit pai. [Capítulo 4](04-commits-e-historico.md)
- **Conflito de merge (*merge conflict*):** situação em que as duas branches mudaram o mesmo trecho e o Git pede que você escolha o texto final. [Capítulo 6](06-branches-stash-e-merge.md)
- **Controle de versão (*version control*):** registro das mudanças de um conjunto de arquivos ao longo do tempo, que permite ver e recuperar qualquer versão. [Capítulo 1](01-por-que-controlar-versoes.md)
- **Controle de versão distribuído (*distributed version control*):** modelo em que cada cópia tem o histórico completo, sem depender de um servidor central. [Capítulo 1](01-por-que-controlar-versoes.md)
- **Credencial (*credential*):** o que prova ao GitHub que você pode enviar (token ou chave SSH); diferente da identidade do autor. [Capítulo 2](02-instalacao-identidade-e-credenciais.md)
- **Detached HEAD:** estado em que o `HEAD` aponta direto para um commit, e não para uma branch. [Capítulo 5](05-desfazendo-erros-com-seguranca.md)
- **Diretório de trabalho (*working directory*):** a pasta do projeto, com os arquivos que você edita. [Capítulo 3](03-como-o-git-pensa.md)
- **Fast-forward:** merge em que a branch de destino só avança o ponteiro, sem criar commit de merge. [Capítulo 6](06-branches-stash-e-merge.md)
- **Fetch:** baixar do remoto os commits novos e atualizar as branches de rastreamento, sem mexer nas suas branches. [Capítulo 8](08-repositorios-remotos.md)
- **Fork:** cópia de um repositório alheio na sua conta do GitHub, onde você pode fazer push. [Capítulo 9](09-colaborando-no-github.md)
- **Gist:** trecho de código ou texto, de um ou poucos arquivos, compartilhado por link; é um repositório Git. [Capítulo 10](10-projeto-curriculo-online.md)
- **Git Credential Manager (GCM):** programa que faz o login no GitHub pelo navegador e guarda a credencial no cofre do sistema. [Capítulo 2](02-instalacao-identidade-e-credenciais.md)
- **Git Flow:** fluxo com as branches fixas `main` e `develop`, mais branches de feature, release e hotfix. [Capítulo 9](09-colaborando-no-github.md)
- **GitHub:** serviço on-line que hospeda repositórios Git e acrescenta issues, pull requests e Pages. [Capítulo 1](01-por-que-controlar-versoes.md)
- **GitHub Flow:** fluxo em que a `main` está sempre pronta e todo trabalho chega a ela por branch curta e pull request. [Capítulo 9](09-colaborando-no-github.md)
- **GitHub Pages:** serviço do GitHub que publica os arquivos de um repositório como site estático, num endereço `github.io`. [Capítulo 10](10-projeto-curriculo-online.md)
- **.gitignore:** arquivo com os padrões de nomes que o Git deve ignorar, como `.env` e `*.log`. [Capítulo 3](03-como-o-git-pensa.md)
- **Hash:** identificador de 40 caracteres hexadecimais calculado do conteúdo, como `9b3de16…`; os primeiros 7 costumam bastar. [Capítulo 3](03-como-o-git-pensa.md)
- **HEAD:** ponteiro para onde você está agora, em geral uma branch; `HEAD~n` é o commit n passos antes. [Capítulo 4](04-commits-e-historico.md)
- **Identidade do autor:** o `user.name` e o `user.email` gravados em cada commit. [Capítulo 2](02-instalacao-identidade-e-credenciais.md)
- **Issue:** registro numerado de tarefa, erro ou pedido no GitHub; `#n` cita, `Closes #n` fecha. [Capítulo 9](09-colaborando-no-github.md)
- **Markdown:** formato de texto com marcações simples (`#`, `-`, `[texto](link)`) que vira página formatada. [Capítulo 10](10-projeto-curriculo-online.md)
- **Merge:** integrar o trabalho de uma branch em outra. [Capítulo 6](06-branches-stash-e-merge.md)
- **Merge de três vias (*three-way merge*):** merge que compara as duas pontas com o ancestral comum e cria um commit com dois pais. [Capítulo 6](06-branches-stash-e-merge.md)
- **origin:** nome padrão do remoto de onde você clonou (ou que você cadastrou primeiro). [Capítulo 8](08-repositorios-remotos.md)
- **Pull:** `fetch` seguido de integração (merge ou rebase) na branch atual. [Capítulo 8](08-repositorios-remotos.md)
- **Pull request (PR):** pedido para integrar uma branch em outra, com espaço para revisão e conversa. [Capítulo 9](09-colaborando-no-github.md)
- **Push:** enviar os seus commits para um remoto. [Capítulo 8](08-repositorios-remotos.md)
- **README:** arquivo (em geral `README.md`) que apresenta o projeto na página do repositório. [Capítulo 10](10-projeto-curriculo-online.md)
- **Rebase:** reaplicar os commits de uma branch em cima de outra base, criando commits novos. [Capítulo 7](07-rebase-e-historico-limpo.md)
- **Rebase interativo (*interactive rebase*):** `git rebase -i`, que permite reescrever, juntar, reordenar e apagar commits locais. [Capítulo 7](07-rebase-e-historico-limpo.md)
- **Reflog:** registro local de onde o `HEAD` e as branches estiveram, que permite achar commits “perdidos”. [Capítulo 5](05-desfazendo-erros-com-seguranca.md)
- **Release:** página do GitHub ligada a uma tag, com notas da versão e arquivos para baixar. [Capítulo 8](08-repositorios-remotos.md)
- **Repositório (*repository*):** o histórico do projeto, guardado na pasta `.git`. [Capítulo 3](03-como-o-git-pensa.md)
- **Repositório remoto (*remote*):** outra cópia do repositório, em geral num servidor, com a qual você troca commits. [Capítulo 8](08-repositorios-remotos.md)
- **Reset:** mover a branch atual para outro commit, com `--soft`, `--mixed` ou `--hard` decidindo o que acontece com as mudanças. [Capítulo 5](05-desfazendo-erros-com-seguranca.md)
- **Restore:** `git restore`, que descarta edições na pasta ou tira arquivos da staging area. [Capítulo 5](05-desfazendo-erros-com-seguranca.md)
- **Revert:** commit novo que desfaz as mudanças de um commit anterior, sem reescrever o histórico. [Capítulo 5](05-desfazendo-erros-com-seguranca.md)
- **Snapshot:** a foto completa dos arquivos rastreados num momento; cada commit guarda uma. [Capítulo 3](03-como-o-git-pensa.md)
- **SSH:** protocolo de acesso por par de chaves (pública e privada), alternativa ao token para falar com o GitHub. [Capítulo 2](02-instalacao-identidade-e-credenciais.md)
- **Staging area (*index*):** a área onde você monta o próximo commit com `git add`. [Capítulo 3](03-como-o-git-pensa.md)
- **Stash:** gaveta onde o Git guarda edições não commitadas para você trocar de branch e trazê-las depois. [Capítulo 6](06-branches-stash-e-merge.md)
- **Tag:** nome fixo para um commit, usado para marcar versões; a anotada tem autor, data e mensagem. [Capítulo 8](08-repositorios-remotos.md)
- **Token de acesso pessoal (*personal access token*):** senha gerada no GitHub, no lugar da senha da conta, para o Git se autenticar por HTTPS. [Capítulo 2](02-instalacao-identidade-e-credenciais.md)
- **Untracked:** estado do arquivo que está na pasta, mas que o Git ainda não acompanha (`??` no `git status -s`). [Capítulo 3](03-como-o-git-pensa.md)
- **upstream:** apelido convencional do repositório original, cadastrado como remoto no clone de um fork; também o nome da branch remota ligada à sua com `push -u`. [Capítulos 8](08-repositorios-remotos.md) e [9](09-colaborando-no-github.md)
