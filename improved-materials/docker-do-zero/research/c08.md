# Dossiê c08: Builds rápidos e imagens enxutas (conferido em 2026-11-26)
## Fatos
- Cache: regras de invalidação (instrução ou arquivos copiados mudam → camada e seguintes refeitas). https://docs.docker.com/build/cache/invalidation/
- Multi-stage: `FROM … AS build`, `COPY --from=build`, `docker build --target`. https://docs.docker.com/build/building/multi-stage/
- Boas práticas: multi-stage, fixar a versão da base, `apt-get update && install --no-install-recommends` no mesmo RUN. https://docs.docker.com/build/building/best-practices/
- Medir: `docker build --progress=plain`, `docker image ls`, `docker history`. Usuário não root: `USER` (testar `docker run --rm img id`).
## Exemplos novos
- Estágio de build instala dependência com pip e copia só o resultado (psycopg na API 1.1).
## Erros comuns
- Medir uma vez só; limpar em RUN separado; alpine com binários glibc.
