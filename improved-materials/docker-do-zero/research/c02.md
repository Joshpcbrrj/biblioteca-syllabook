# Dossiê c02: Docker Desktop no Windows: ativar e instalar
Conferido em 2026-11-26.

## Fatos
- Requisitos WSL 2: WSL 2.1.5 ou superior; Windows 10 22H2 (build 19045) Pro/Enterprise/Education ou Windows 11 23H2 (build 22631) ou superior (Pro/Enterprise/Education); serviço "Servidor" (LanmanServer) ativo com início Automático; CPU 64 bits com SLAT; 8 GB RAM; virtualização ligada na BIOS/UEFI. https://docs.docker.com/desktop/setup/install/windows-install/ (2026-11-26)
- Windows Home: só contêineres Linux (WSL 2). Contêineres Windows exigem Pro/Enterprise e instalação para todos os usuários.
- Três backends: WSL 2 (padrão), Hyper-V (só instalação "todos os usuários") e Docker VMM (Beta). Desde a versão 4.97 a página de configuração do instalador lista os backends como opções.
- Dois modos: por usuário (recomendado, sem admin, em `%LOCALAPPDATA%\Programs\DockerDesktop`) e todos os usuários (admin; `C:\Program Files\Docker\Docker`). Trocar de modo exige desinstalar e reinstalar.
- Linha de comando: `"Docker Desktop Installer.exe" install --user`; PowerShell `Start-Process 'Docker Desktop Installer.exe' -Wait -ArgumentList 'install','--user'`.
- Instalação "todos": grupo `docker-users` (`net localgroup docker-users <user> /add`); dá poder equivalente a administrador; com WSL 2 não é necessário.
- Não inicia sozinho depois de instalar; aceitar o Subscription Service Agreement na primeira abertura.
- Integração WSL: Settings > Resources > WSL integration (por distro); dados do WSL em `C:\Users\<user>\AppData\Local\Docker\wsl`. Desinstalar Docker Engine dentro do WSL antes. https://docs.docker.com/desktop/features/wsl/ (2026-11-26)
- Esta máquina: Windows 11 Pro (10.0.26300), WSL 2 com `Ubuntu-26.04` e `docker-desktop`; contexts `default` e `desktop-linux` (ativo). Comandos de verificação executáveis aqui: `wsl --version`, `wsl -l -v`, `docker version`, `docker context ls`, `docker run --rm hello-world`. Instalação em si: **não executada** (já instalado).

## Exemplos novos
- Checklist de requisitos com `winver`, `wsl --version`, `systeminfo | findstr /i "Hyper-V"` (Hyper-V requirements) — rodar aqui e usar a saída real, sem expor dados pessoais.

## Erros comuns
- Virtualização desligada na BIOS (aparece como erro do WSL "Virtual Machine Platform"/"HCS"); WSL desatualizado (`wsl --update`); Desktop aberto mas Engine "starting"; docker instalado também dentro do WSL (conflito).
- Windows Server não é suportado.
