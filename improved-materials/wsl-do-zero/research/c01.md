# Dossiê cap. 1: O que é o WSL e quando usar (conferido em 2026-11-27)
- WSL: camada que roda Linux no Windows sem VM manual nem dual boot; instalável com `wsl --install` (Win 10 build 19041+ ou Win 11). https://learn.microsoft.com/windows/wsl/install (2026-11-27)
- WSL 1 × 2: WSL 2 tem kernel Linux completo numa VM gerenciada; WSL 1 traduz chamadas; WSL 1 ganha em desempenho entre sistemas de arquivos; WSL 2 tem systemd e compatibilidade total de syscalls; WSL 2 até 20× mais rápido ao descompactar tarball, 2–5× em git clone/npm install (versões iniciais). https://learn.microsoft.com/windows/wsl/compare-versions (2026-11-27)
- Kernel do WSL 2: construído pela Microsoft da branch estável do kernel.org, atualizado via Windows Update/`wsl --update`, código aberto (microsoft/WSL2-Linux-Kernel). Aqui: `uname -r` = 6.18.58.1-microsoft-standard-WSL2 (nome termina em `microsoft-standard-WSL2`). (2026-11-27)
- WSL em código aberto: repositório microsoft/WSL, release 3.0.5 de 03/11/2026. https://github.com/microsoft/WSL/releases (2026-11-27)
- VM × WSL × dual boot: comparação própria; VirtualBox/VMware: WSL 2 funciona com VMware 15.5.5+; VirtualBox tem restrições (compare-versions).
- Verificação do PC: virtualização habilitada no firmware (Gerenciador de Tarefas → Desempenho → CPU → Virtualização). `systeminfo` mostra "Requisitos do Hyper-V"; no Win 11 o comando `wsl --status` e `wsl --version` já dizem se está instalado. Comando PowerShell para virtualização: `(Get-CimInstance Win32_Processor).VirtualizationFirmwareEnabled` (testar na produção).
- Erro comum: achar que WSL = VM que o usuário gerencia; achar que `/mnt/c` é o lugar do projeto (cap. 4).
