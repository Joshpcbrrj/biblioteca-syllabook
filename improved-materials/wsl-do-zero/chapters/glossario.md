# Glossário

Um termo por linha, em ordem alfabética, com o termo em inglês quando ele é diferente e o link para o capítulo que o explica.

- **9p:** protocolo da ponte entre o Linux e os discos do Windows; é mais lento que o ext4. [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **`appendWindowsPath`:** opção do `wsl.conf` que decide se o `PATH` do Windows entra no do Ubuntu. [Capítulo 7](07-gerenciar-o-wsl.md)
- **`apt`:** gerenciador de pacotes do Ubuntu; o `update` renova a lista e o `upgrade` atualiza o que está instalado. [Capítulo 3](03-primeiros-passos-no-ubuntu.md)
- **`backup.ps1`:** script do projeto que exporta a distro com data, grava o SHA-256 e, com `-Testar`, prova a restauração num clone. [Capítulo 8](08-backup-e-restauracao.md)
- **`bootstrap.sh`:** script idempotente do projeto que reinstala as ferramentas e liga os dotfiles numa distro nova. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **Claude Code:** assistente de programação da Anthropic que roda no terminal; no livro, instalado como usuário dentro do WSL. [Capítulo 9](09-claude-code-no-wsl.md)
- **`claude doctor`:** comando do Claude Code que diagnostica a instalação, só lendo, sem abrir sessão. [Capítulo 9](09-claude-code-no-wsl.md)
- **`CLAUDE.md`:** arquivo do projeto com o contexto e as regras que o Claude Code lê; orienta, mas não é uma barreira. [Capítulo 9](09-claude-code-no-wsl.md)
- **Clone de teste** (*test clone*): a mesma distro restaurada com outro nome (`teste-...`), para provar o backup e testar sem risco. [Capítulo 8](08-backup-e-restauracao.md)
- **CRLF × LF:** as duas formas de marcar o fim de linha; o Windows grava `\r\n` e o Linux `\n`. [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **`DISPLAY`:** variável que diz aos programas Linux com janela onde desenhar; o WSLg a define. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **Distro** (*distribution*): um Linux completo em volta do kernel, como o Ubuntu ou o Debian. [Capítulo 2](02-instalacao-do-wsl-e-do-ubuntu.md)
- **Distro de teste** (*test distro*): distro à parte, só para experimentar o que é perigoso sem tocar nas suas. [Capítulo 8](08-backup-e-restauracao.md)
- **Dotfiles:** arquivos de configuração do `~` (como `.bashrc`), guardados no repositório e ligados por link simbólico. [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **Dual boot:** dois sistemas instalados no mesmo disco, um por vez, com reinício para trocar. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **`explorer.exe`:** o Explorador de Arquivos do Windows; `explorer.exe .` abre a pasta atual do Linux nele. [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **ext4:** sistema de arquivos do disco do Linux, o mais rápido para projetos dentro do WSL. [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **Firmware (BIOS/UEFI):** programa da placa-mãe onde a virtualização precisa estar ligada para o WSL 2 funcionar. [Capítulo 2](02-instalacao-do-wsl-e-do-ubuntu.md)
- **`.gitattributes`:** arquivo do repositório que fixa o fim de linha (por exemplo, `*.sh text eol=lf`). [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **Hipervisor** (*hypervisor*): camada que cria e gerencia máquinas virtuais; o WSL 2 usa a do Windows. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **Idempotente** (*idempotent*): que dá o mesmo resultado se rodado uma ou várias vezes. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **Imagem `.wsl`:** arquivo da distro, com hash SHA-256, que permite instalar sem a loja. [Capítulo 2](02-instalacao-do-wsl-e-do-ubuntu.md)
- **Kernel:** o núcleo do sistema, que fala com o hardware e atende os pedidos dos programas; no WSL 2, o nome termina em `microsoft-standard-WSL2`. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **Link simbólico** (*symlink*): arquivo que aponta para outro; liga os dotfiles do repositório ao `~`. [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **Locale:** idioma e formatos (data, número) do Linux; muda com `language-pack-pt` e `update-locale`. [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **Marketplace:** catálogo de onde o Claude Code instala plugins. [Capítulo 9](09-claude-code-no-wsl.md)
- **MCP** (*Model Context Protocol*): programa à parte que dá ferramentas ao Claude Code; registra-se com `claude mcp add`. [Capítulo 9](09-claude-code-no-wsl.md)
- **`meu-ambiente`:** repositório Git do projeto do livro, com os verificadores, os dotfiles, o `bootstrap.sh` e o `backup.ps1`. [Capítulo 3](03-primeiros-passos-no-ubuntu.md)
- **`/mnt/c`:** pasta do Linux pela qual o disco `C:` do Windows aparece; os outros discos seguem a mesma ideia (`/mnt/d`). [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **Modos de permissão** (*permission modes*): `default`, `acceptEdits`, `plan` e `auto`, que definem o que o Claude Code faz sem perguntar. [Capítulo 9](09-claude-code-no-wsl.md)
- **Nerd Font:** fonte com ícones extras, que o Starship usa; instala-se no Windows. [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **nvm:** gerenciador de versões do Node.js, na pasta pessoal. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **`PATH`:** lista de pastas onde o shell procura programas; vale o primeiro que achar. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **Perfil** (*profile*): conjunto de configurações de uma aba do Windows Terminal (programa, esquema de cores, fonte). [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **Plan:** no Spec Kit, o documento que diz como construir: linguagem, bibliotecas e estrutura. [Capítulo 10](10-projeto-final-um-app-com-spec-kit.md)
- **Plugin:** pacote de um marketplace que acrescenta comandos (e às vezes hooks e MCPs) ao Claude Code. [Capítulo 9](09-claude-code-no-wsl.md)
- **Prompt:** o texto que o terminal mostra antes do cursor, com usuário, computador e pasta; termina em `$` (usuário comum) ou `#` (root). [Capítulo 3](03-primeiros-passos-no-ubuntu.md)
- **root:** o administrador do Linux; o que ele cria pertence a ele, por isso não se trabalha como root. [Capítulo 3](03-primeiros-passos-no-ubuntu.md)
- **SDD** (*Spec-Driven Development*): desenvolver guiado pela especificação: primeiro o que o programa faz, depois como, depois as tarefas, e só no fim o código. [Capítulo 10](10-projeto-final-um-app-com-spec-kit.md)
- **SDKMAN:** gerenciador de kits de desenvolvimento, como o Java. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **SHA-256:** impressão digital de um arquivo; confere que a cópia está íntegra. [Capítulo 8](08-backup-e-restauracao.md)
- **Spec** (*specification*): no Spec Kit, o documento que diz o quê e por quê, sem tecnologia. [Capítulo 10](10-projeto-final-um-app-com-spec-kit.md)
- **`specify`:** o CLI do Spec Kit; o `specify init` cria o `.specify/` e os comandos em `.claude/skills/`. [Capítulo 10](10-projeto-final-um-app-com-spec-kit.md)
- **Spec Kit:** conjunto de ferramentas da GitHub para o Spec-Driven Development; traz o CLI `specify` e os comandos `/speckit-*`. [Capítulo 10](10-projeto-final-um-app-com-spec-kit.md)
- **Starship:** programa que gera o prompt do terminal; ligado por uma linha no `~/.bashrc`. [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **`sudo`:** roda um comando como root, pedindo a sua senha. [Capítulo 3](03-primeiros-passos-no-ubuntu.md)
- **Swap:** arquivo de troca que a máquina virtual usa quando falta memória; por padrão, 25% da memória. [Capítulo 7](07-gerenciar-o-wsl.md)
- **`systemd`:** o processo 1 do Linux, que liga e cuida dos serviços; no WSL, ligado por `[boot] systemd=true`. [Capítulo 3](03-primeiros-passos-no-ubuntu.md)
- **Tela de confiança** (*trust dialog*): pergunta do Claude Code ao abrir uma pasta; confie só em pastas de projeto. [Capítulo 9](09-claude-code-no-wsl.md)
- **`--terminate`** × **`--shutdown`:** o primeiro para uma distro; o segundo para todas e a máquina virtual. [Capítulo 7](07-gerenciar-o-wsl.md)
- **`--unregister`:** apaga a distro e o disco dela; só com backup conferido e o nome exato. [Capítulo 7](07-gerenciar-o-wsl.md)
- **Usuário padrão** (*default user*): o usuário com que a distro abre; numa distro importada, vem da seção `[user]` do `wsl.conf`. [Capítulo 8](08-backup-e-restauracao.md)
- **uv:** gerenciador de projetos e versões do Python. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **`verificar.ps1` e `verificar.sh`:** os verificadores do projeto, um para cada lado, que provam a cada capítulo que o ambiente funciona. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **Virtualização** (*virtualization*): recurso do processador que permite rodar máquinas virtuais; precisa estar ligado no firmware. [Capítulo 2](02-instalacao-do-wsl-e-do-ubuntu.md)
- **VM** (*virtual machine*, máquina virtual): sistema inteiro rodando numa janela, dentro de outro. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **Windows Terminal:** o aplicativo do Windows que abre as abas de PowerShell e de distros; guarda cores e fonte no `settings.json`. [Capítulo 5](05-o-terminal-do-seu-jeito.md)
- **`\\wsl$`:** caminho do Windows para os arquivos de uma distro do WSL, no formato `\\wsl$\<distro>`. [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
- **WSL** (*Windows Subsystem for Linux*): recurso do Windows que roda um Linux de verdade dentro dele. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **WSL 1 × WSL 2:** o WSL 1 traduz as chamadas do Linux; o WSL 2 tem um kernel Linux completo numa VM leve e é o padrão. [Capítulo 1](01-o-que-e-o-wsl-e-quando-usar.md)
- **`wsl.conf`:** arquivo `/etc/wsl.conf` de cada distro (systemd, usuário padrão, `PATH` do Windows); vale depois de `wsl --terminate`. [Capítulo 7](07-gerenciar-o-wsl.md)
- **`.wslconfig`:** arquivo na pasta de usuário do Windows com os limites da máquina virtual (memória, processadores, swap); vale para todas as distros e exige `wsl --shutdown`. [Capítulo 7](07-gerenciar-o-wsl.md)
- **`wsl --export` e `wsl --import`:** gravam a distro num `.tar` e criam uma distro nova a partir dele. [Capítulo 8](08-backup-e-restauracao.md)
- **WSLg:** parte do WSL que mostra programas Linux com janela no desktop do Windows. [Capítulo 6](06-ferramentas-de-desenvolvimento-e-programas.md)
- **`wslpath`:** comando que converte caminhos entre o formato do Linux (`-u`) e o do Windows (`-w`). [Capítulo 4](04-arquivos-entre-linux-e-windows.md)
