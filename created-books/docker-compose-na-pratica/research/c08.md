# Dossiê c08 · Ordem de início e saúde

## Fatos (conferidos em 2026-11-20) — https://docs.docker.com/compose/how-tos/startup-order/ · https://docs.docker.com/reference/compose-file/workload-spec/
- depends_on: `service_started`, `service_healthy`, `service_completed_successfully`; forma longa com `restart: true` e `required` (padrão true, 2.20.0+)
- healthcheck: `test`, `interval`, `timeout`, `retries`, `start_period`, `start_interval`, `disable`
- `test` em string = `CMD-SHELL`; exemplo `["CMD", "curl", "-f", "http://localhost"]`
- Padrões iguais ao HEALTHCHECK do Dockerfile (a página não dá números: conferir na referência do Dockerfile antes de citar)

## Erros comuns
- depends_on curto só espera o contêiner iniciar, não o banco aceitar conexão
- Teste de saúde com ferramenta que a imagem não tem (curl em imagem alpine)

## Testado (Compose v5.7.0, 2026-11-21), projeto contador com rota /saude
- Sem espera: curl logo após up -> `curl: (52) Empty reply from server`, depois `Sem banco: ... Connection refused`, depois `Visita número 1`
- `depends_on: [db]` (service_started): ordena db antes da api, mas o curl imediato falha igual
- db: `pg_isready -h localhost -U postgres` (interval 2s, timeout 3s, retries 10) -> saída `/var/run/postgresql:5432 - accepting connections`
- Logs do 1º init mostram servidor temporário: "ready to accept connections", shutdown, e de novo ready; por isso `-h localhost` (TCP)
- api: healthcheck com python urllib em /saude (imagem slim sem curl); `up -d --wait` -> primeiro curl `Visita número 1` em 3 rodadas
- `up -d` sem --wait com service_healthy: a api inicia só depois do db healthy; status `(health: starting)`
- curl no postgres -> `exec: "curl": executable file not found in $PATH`; up: `dependency failed to start: container contador-db-1 is unhealthy`; api em `Created`
- `["CMD", "redis-cli ping"]` -> `exec: "redis-cli ping": executable file not found`; `redis-cli ping` -> `PONG`
- nginx alpine: `wget -q --spider http://localhost/` -> healthy; com :8080 -> unhealthy

## Analogia: onde para de valer (teste de 2026-11-21)
- alpine:3.20 com healthcheck `test -f /tmp/ok` (interval 2s, retries 2), `restart: unless-stopped`, outro serviço com `depends_on: condition: service_healthy`. Depois do `up -d --wait`, `rm /tmp/ok`: após 10 s, `saude-db-1 Up 14 seconds (unhealthy)`, `RestartCount=0`, `saude-api-1 Up 11 seconds`. O Docker não reinicia contêiner unhealthy, e o depends_on só vale na partida.
