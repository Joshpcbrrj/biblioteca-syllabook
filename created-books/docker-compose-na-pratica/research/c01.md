# Dossiê c01 · Por que um arquivo para o projeto

## Fatos (conferidos em 2026-11-20)
- Serviço: mesma imagem e configuração rodando uma ou mais vezes ("same container image, and configuration, one or more times") — https://docs.docker.com/compose/intro/compose-application-model/
- Projeto: "an individual deployment of an application specification"; nome via atributo `name` no topo — idem
- Arquivo padrão: `compose.yaml` (preferido) ou `compose.yml`; `docker-compose.yaml`/`.yml` só por compatibilidade; se ambos existem, vence `compose.yaml` — idem
- Nome padrão do projeto = nome da pasta — https://docs.docker.com/compose/how-tos/networking/
- Rede padrão `<projeto>_default` — idem
- Testado local (Engine 29.9.2, Compose v5.6.1): `docker compose up -d` na pasta meu-site criou a rede `meu-site_default` e o contêiner `meu-site-web-1`
- Retestado em 2026-11-20 com a nova referência (Engine 29.9.3, Compose v5.7.0): sem TTY, `up -d` imprime `Network meu-site_default Creating` (2x), `Created` (2x), `Container meu-site-web-1 Creating/Created/Starting/Started`; `config`, `no configuration file provided: not found`, `No such container: web`, `port is already allocated`, nomes `blog-blog-1`, `painel-*-1`, rede `painel_default`: iguais
- `env:` no lugar de `environment:` (v5.7.0): `validating ...compose.yaml: services.adminer.env false schema`
- Testado: sem arquivo -> `no configuration file provided: not found`
- Testado: `docker compose config` mostra `name: meu-site` e expande ports para `target: 80`, `published: "8080"`

## Exemplo do livro
- docker run com --name, -p 8080:80, -v ./site:...:ro, -e TZ, --restart unless-stopped, nginx:1.27-alpine -> o mesmo em compose.yaml (serviço web)

## Erros comuns
- Rodar `docker compose` fora da pasta do arquivo
- Achar que o Compose substitui o Docker (usa o mesmo Engine)
- Confundir serviço (definição) com contêiner (instância)
