# Dossiê c06 · Vários serviços e a rede do projeto

## Fatos (conferidos em 2026-11-20) — https://docs.docker.com/compose/how-tos/networking/
- Rede padrão `<projeto>_default`, driver bridge
- O nome do serviço resolve como hostname (DNS interno): exemplo `postgres://db:5432`
- Entre serviços vale a porta do contêiner, não a publicada
- `expose` mostra a porta a outros serviços sem publicar no host
- `network_mode: host` não tem DNS por nome de serviço

## Erros comuns
- API usando `localhost` para achar o banco
- Usar a porta publicada em vez da interna (5432)
- Publicar a porta do banco sem necessidade

## Ligações
- c08 resolve "o banco ainda não está pronto" com healthcheck

## Imagem postgres (2026-11-21) — https://hub.docker.com/_/postgres
- `POSTGRES_PASSWORD` é a única variável obrigatória; superusuário padrão `postgres`
- postgres:17: `PGDATA=/var/lib/postgresql/data`, `VOLUME /var/lib/postgresql/data` (conferido também com `docker image inspect`); no 18+ o volume mudou para `/var/lib/postgresql`
- Variáveis `POSTGRES_*` e scripts de init só valem com o diretório de dados vazio

## Testado (Compose v5.7.0, 2026-11-21): projeto contador (api Python + psycopg 3.3.9, db postgres:17.12)
- `DB_HOST: banco` -> `failed to resolve host 'banco': [Errno -2] Name or service not known`
- `DB_HOST: localhost` -> `connection to server at "127.0.0.1", port 5432 failed: Connection refused`
- porta publicada usada dentro da rede (15432) -> `connection to server at "172.20.0.3", port 15432 failed: Connection refused`
- 5433 ocupada no host do autor -> `Bind for 127.0.0.1:5433 failed: port is already allocated`
- Adminer com servidor `db` faz login e vê a tabela `visitas`

## Porta presa a 127.0.0.1 (acréscimo de 2026-11-21) — https://docs.docker.com/engine/network/port-publishing/
- Página "Port publishing and mapping": aviso em destaque "Publishing container ports is insecure by default."; sem endereço, o daemon publica em todos os endereços do host (`0.0.0.0` e `[::]`); com `127.0.0.1`, "only the Docker host can access the published container port".
- Testado (Compose v5.7.0, Docker Desktop no Windows 11, máquina 192.168.1.15):
  - `"8000:8000"`: `docker compose port api 8000` -> `0.0.0.0:8000`; `docker port contador-api-1` -> `8000/tcp -> 0.0.0.0:8000` e `8000/tcp -> [::]:8000`; `curl -s 192.168.1.15:8000` -> `Visita número 3`.
  - `"127.0.0.1:8000:8000"`: `port` -> `127.0.0.1:8000`; `docker port` -> só `8000/tcp -> 127.0.0.1:8000`; `curl localhost:8000` -> `Visita número 4`; `curl -sS 192.168.1.15:8000` -> `curl: (7) Failed to connect to 192.168.1.15:8000 after 2012 ms: Could not connect to server`; `ps` -> `127.0.0.1:8000->8000/tcp`; `config` -> `host_ip: 127.0.0.1`.
  - `"127.0.0.1:15432:5432"` no db: `docker compose port db 5432` -> `127.0.0.1:15432`; pela 192.168.1.15 -> curl (7).
  - Trocar para 127.0.0.1 logo depois de vários curl (conexões em TIME_WAIT no Windows): `ports are not available: exposing port TCP 127.0.0.1:8000 -> 127.0.0.1:0: listen tcp4 127.0.0.1:8000: bind: Only one usage of each socket address (protocol/network address/port) is normally permitted.` (reproduzido 2 vezes); rodar o `up -d` de novo alguns segundos depois resolveu.
