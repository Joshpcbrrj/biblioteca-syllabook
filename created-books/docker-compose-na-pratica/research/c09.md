# Dossiê c09 · Comandos do dia a dia

## Fatos (conferidos em 2026-11-20) — https://docs.docker.com/reference/cli/docker/compose/exec/ · /run/ · https://docs.docker.com/reference/compose-file/services/
- exec: `-d`, `-e`, `--index`, `-T`, `-u`, `-w`; aloca TTY por padrão; precisa do contêiner rodando
- run: `--rm`, `-d`, `-e`, `-p`, `-P/--service-ports`, `--no-deps`, `--entrypoint`, `-v`; não publica as portas do serviço sem `--service-ports`; sobe dependências salvo `--no-deps`
- restart: `no` (padrão), `always`, `on-failure[:max-retries]`, `unless-stopped`

## Erros comuns
- run sem --rm deixa contêineres sobrando
- Esperar que run publique as portas

## Conferido em 2026-11-21 (docs exec/run/stop/start/restart/services) e testado (Compose v5.7.0)
- restart: no = padrão, nunca; always = sempre, até a remoção; on-failure[:n] = código de erro; unless-stopped = qualquer código, para quando o serviço é parado ou removido
- `restart` (comando): "changes are not reflected" — testado: DB_HOST trocado, restart manteve o antigo; up -d recriou
- run: não cria portas sem --service-ports; --no-deps; nome `contador-api-run-<código>`; respeita depends_on (Waiting/Healthy)
- `down` não remove contêineres de run: `Network contador_default Resource is still in use`; `down --remove-orphans` remove
- exec em serviço parado: `service "api" is not running`; exec -T para scripts
- Queda simulada: `os.kill(1, signal.SIGINT)` -> KeyboardInterrupt, `Exited (130)`; com unless-stopped/on-failure volta (RestartCount=1)
- stop: api `Exited (137)`, db `Exited (0)`; always e unless-stopped não reiniciam após stop

## Acréscimo aprovado em 2026-11-21: command, entrypoint e docker compose cp
Fontes conferidas em 2026-11-21: https://github.com/compose-spec/compose-spec/blob/main/container_spec.md (a página container-spec em docs.docker.com deu 404) · https://docs.docker.com/reference/cli/docker/compose/cp/

### Fatos
- `command` "overrides the default command declared by the container image" (CMD); string ou lista; a forma string não passa pelo `SHELL` da imagem; `null` = CMD da imagem; `[]`/`''` = vazio
- `entrypoint` substitui o ENTRYPOINT; "If `entrypoint` is non-null, Compose ignores any default command from the image"; `null` = o da imagem; `[]`/`''` = vazio
- `docker compose cp [OPTIONS] SERVICE:SRC_PATH DEST_PATH|-` e `SRC_PATH|- SERVICE:DEST_PATH`; opções `--all`, `-a/--archive`, `-L/--follow-link`, `--index`

### Testado (Compose v5.7.0, Docker Desktop no Windows)
- `docker image inspect`: contador-api E=null C=["python","-u","app.py"]; postgres:17 E=["docker-entrypoint.sh"] C=["postgres"]
- `command: postgres -c log_statement=all`: Entrypoint mantido, Cmd=["postgres","-c","log_statement=all"]; logs com `LOG:  statement: ...`; config divide a string em lista
- `entrypoint: ["python","-u"]` sem command: Cmd=null, `exited (0)`; com `command: ["app.py"]` volta a funcionar
- `run --rm --no-deps api -c "..."` troca só o command; `--entrypoint python api --version` -> Python 3.13.18
- Erro: `entrypoint: ["postgres"]` -> `"root" execution of the PostgreSQL server is not permitted.`; com restart, `Restarting (1)`
- cp: `pg_dump -t visitas -f /tmp/visitas.sql` + `cp db:/tmp/visitas.sql ./visitas.sql` (2.095 bytes, 120 linhas; saída Copying/Copied); host -> contêiner `cp nota.txt api:/app/nota.txt`
- Arquivo copiado some depois de down + up -d
- Erros: nome do contêiner -> `no container found for service "contador-db-1"`; caminho inexistente -> `Could not find the file /tmp/nao-existe.sql in container ...`
