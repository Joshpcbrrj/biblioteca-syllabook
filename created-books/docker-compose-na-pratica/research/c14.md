## Acréscimo aprovado em 2026-11-21: build multi-stage com target e push
Fontes conferidas em 2026-11-21: https://docs.docker.com/reference/compose-file/build/ · https://docs.docker.com/build/building/multi-stage/ · https://docs.docker.com/reference/cli/docker/compose/push/

### Fatos
- `target` "defines the stage to build as defined inside a multi-stage Dockerfile"
- `FROM ... AS <nome>`; um estágio pode partir de outro (`FROM base AS dev`); BuildKit só constrói os estágios de que o alvo depende; sem target, o último estágio
- image + build: sem `pull_policy`, o Compose tenta baixar a imagem primeiro e constrói se ela não existir; o push "doesn't try to push service images without an image attribute"
- O nome da imagem diz o destino: `localhost:5000/...` = registro local; `usuario/imagem` = Docker Hub
- push: `--ignore-missing`, `--include-deps`, `-q`

### Testado (Compose v5.7.0, Docker Desktop no Windows)
- Dockerfile base/dev/prod (prod por último, `useradd --system --no-create-home app`, `USER app`); compose.yaml `target: prod`, override `target: dev` (o context da base continua)
- Dev: whoami root, Cmd com `-X dev`; prod com --build: whoami app; a API lê o secret como app
- Erro: os dois estágios com o mesmo nome `stack-api` -> prod sem --build depois do dev subiu a imagem dev (root)
- Erro: `target: producao` -> `failed to solve: target stage "producao" could not be found`
- Registro local: `docker run -d -p 5000:5000 --name registro registry:2`; `image: localhost:5000/stack-api:1.0` no compose.prod.yaml; build -> `Image ... Built`; push -> `... Pushed`; `/v2/_catalog` e `/v2/stack-api/tags/list`
- Sem a imagem local, o `up` de produção sem --build fez `Pulling`/`Pulled`
