# Dossiê c10 · Desenvolvimento com watch

## Fatos (conferidos em 2026-11-20) — https://docs.docker.com/compose/how-tos/file-watch/
- `develop.watch` com regras: `action` (`sync`, `rebuild`, `sync+restart`), `path`, `target`, `ignore`, `initial_sync`
- path relativo ao projeto, sem globs; respeita .dockerignore
- A imagem precisa de `stat`, `mkdir`, `rmdir`; só serviços com `build`
- Comandos: `docker compose watch` ou `docker compose up --watch` (`-w`)
- `sync+exec` (aprovado para o c10 em 2026-11-21): sincroniza os arquivos conforme `target` e depois executa um comando dentro do contêiner, sem reiniciá-lo; disponível desde Compose 2.32.0 — https://docs.docker.com/reference/compose-file/develop/ (2026-11-21)
- Campos de `exec`: `command` (obrigatório; forma shell ou exec), `user`, `privileged`, `working_dir`, `environment` (somam/sobrescrevem as do serviço) — idem
- Exemplo oficial: `path: ./etc/config`, `action: sync+exec`, `target: /etc/config/`, `exec: {command: app reload}` — idem
- A página how-to (file-watch) ainda não documenta `sync+exec`; usar a especificação `develop`
- Contradição na doc: diz que `target` só vale para `sync`, mas o exemplo de `sync+exec` usa `target`; testar ao escrever
- Notas da v5.7.0 (2 nov.): "Fix(watch): skip sync+exec triggers on bind-mounted paths" (#14328) — https://github.com/docker/compose/releases; um caminho com bind mount não dispara o exec
- Correção: a nota anterior (o recurso "aparece nas notas da 5.7.0") induzia a achar que era novo; ele já existia na referência anterior

## Testado (Compose v5.7.0, Windows 11 + Docker Desktop, 2026-11-21) — projeto vitrine (nginx com build + ola-api)
- sync (pasta -> pasta), sync+restart (`Restarting`, `service(s) ["api"] restarted`), sync+exec (`nginx -s reload`, SIGHUP nos logs), rebuild (`Rebuilding service(s)`, `Recreate`): todos funcionaram
- target no sync+exec (resolve a contradição da doc): sem target -> `services.web.develop.watch: target is required for non-rebuild actions: invalid compose project`; arquivo -> funciona; pasta `/etc/nginx/conf.d/` com path arquivo -> aviso `cannot overwrite directory "etc/nginx/conf.d" with non-directory "/"`, sem cópia; caminho errado `/etc/nginx/default.conf` -> copia para o lugar errado, reload, sem erro
- CORREÇÃO: sync funciona em serviço só com image; só rebuild exige build: `can't watch service "web" with action rebuild without a build context`
- `docker compose watch`: sem logs dos serviços; Ctrl+C deixa os contêineres rodando. `up --watch`: Ctrl+C para os contêineres
- Teste com roteiro próprio teve falhas intermitentes (arquivo não atualizado) que não se repetiram em 7 rodadas seguintes; causa não identificada, provavelmente do roteiro (não do Compose)
- `up --watch` sem --build reaproveita imagem antiga do mesmo projeto
