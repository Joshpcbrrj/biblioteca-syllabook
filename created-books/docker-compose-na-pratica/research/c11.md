# Dossiê c11 · Perfis e arquivos sobrepostos

## Fatos (conferidos em 2026-11-20) — https://docs.docker.com/compose/how-tos/profiles/ · https://docs.docker.com/compose/how-tos/multiple-compose-files/merge/
- Serviço sem profiles sempre sobe; com profiles, só com o perfil ativo
- `--profile debug` ou `COMPOSE_PROFILES=debug` (lista com vírgula); `--profile "*"` ativa todos
- Serviço citado na linha de comando sobe mesmo com o perfil desligado (com dependências)
- Por padrão lê compose.yaml + compose.override.yaml; com -f, junta na ordem dada
- Merge: valores únicos substituídos; ports/expose/dns concatenados; environment/labels por chave; volumes pelo caminho no contêiner
- Caminhos relativos a partir do primeiro -f
- Resolvido (teste 2026-11-21): com -f, o compose.override.yaml não é lido (`-f compose.yaml config` sem a porta 15432)

## Conferido em 2026-11-21 — https://docs.docker.com/reference/compose-file/merge/
- `!override` substitui o atributo inteiro, ignorando o merge; `!reset` apaga (`!reset []`, `!reset null`); a página não cita versão mínima
- Sequências são somadas; ports usam a chave única {ip, target, published, protocol}

## Testado (Compose v5.7.0), projeto contador
- adminer com `profiles: [ferramentas]`: fora do up comum; `--profile`, `COMPOSE_PROFILES`, `--profile "*"`, nome explícito sobe só o adminer
- `down` sem perfil deixa o adminer e falha a rede: `Network contador_default Resource is still in use`
- `compose.override.yaml` lido sozinho (db 15432); `-f compose.yaml -f compose.prod.yaml`: api com 8000 E 80 (soma), db sem porta
- `ports: !override` -> só 80; `ports: !reset []` -> sem portas; `profiles: !reset []` no override -> adminer sobe sempre; `profiles: []` sem tag não muda nada
- environment junta por chave (DB_HOST, DB_SENHA, MODO); healthcheck parcial junta (interval trocado, resto mantido); image trocada
- `profile:` no singular -> `services.carga.profile false schema`
